# RS-232

The C64 implements RS-232 serial communications through a software-emulated
UART using CIA #2 and the User Port. Unlike a hardware UART, the RS-232
implementation is entirely software-driven via NMI interrupts.

## RS-232 Hardware Connection

RS-232 signals are connected through the User Port (CIA #2 Port B and
bit 2 of Port A):

| Signal | Abbreviation | User Port Pin | CIA #2 Port | Bit |
|---|---|---|---|---|
| Received Data | SIN | C | Port B | 0 |
| Request to Send | RTS | D | Port B | 1 |
| Data Terminal Ready | DTR | E | Port B | 2 |
| Ring Indicator | RI | F | Port B | 3 |
| Carrier Detect | DCD | H | Port B | 4 |
| (User defined) | — | J | Port B | 5 |
| Clear to Send | CTS | K | Port B | 6 |
| Data Set Ready | DSR | L | Port B | 7 |
| Transmitted Data | SOUT | M | Port A | 2 |

## Software-Emulated 6551 Registers

The Kernal emulates a MOS 6551 ACIA UART in RAM at $0293–$0297:

### $0293 — M51CTR: Control Register

Set by the first character of the filename when opening device 2.

| Bit(s) | Function |
|---|---|
| 7 | Stop bits: 0 = 1 stop bit, 1 = unused (always treated as having stop bits) |
| 6–5 | Word length: 00 = 8 bit, 01 = 7 bit, 10 = 6 bit, 11 = 5 bit |
| 4 | Unused |
| 3–0 | Baud rate (see table) |

### Baud Rate Table

| Value | Baud Rate | Implemented? |
|---|---|---|
| 0 | User-defined | No |
| 1 | 50 | Yes |
| 2 | 75 | Yes |
| 3 | 110 | Yes |
| 4 | 134.5 | Yes |
| 5 | 150 | Yes |
| 6 | 300 | Yes |
| 7 | 600 | Yes |
| 8 | 1200 | Yes |
| 9 | (user) | No |
| 10 | 2400 | Yes |
| 11–15 | 3600–19200 | No |

### $0294 — M51CDR: Command Register

Set by the second character of the filename when opening device 2.

| Bit(s) | Function |
|---|---|
| 7–5 | Parity: xx0 = none, 001 = odd, 011 = even, 101 = mark, 111 = space |
| 4 | Duplex: 0 = full, 1 = half |
| 3–1 | Unused |
| 0 | Handshake: 0 = 3-line, 1 = X-line |

### $0295–$0296 — M51AJB: Nonstandard Baud Rate

Intended for user-defined baud rates. Formula:
`VALUE = (CLOCK / BAUD / 2) - 100`. Not implemented in the Kernal.

### $0297 — RSSTAT: Status Register

| Bit | Value | Meaning |
|---|---|---|
| 7 | 128 | Break detected |
| 6 | 64 | DSR signal missing |
| 5 | — | Unused |
| 4 | 16 | CTS signal missing |
| 3 | 8 | Receiver buffer empty |
| 2 | 4 | Receiver buffer overrun |
| 1 | 2 | Framing error |
| 0 | 1 | Parity error |

Reading this register (via ST or READST) clears it to 0.

## Buffer Management

When device 2 is opened, the Kernal allocates two 256-byte FIFO buffers
at the top of BASIC memory:

| Buffer | Purpose | Size |
|---|---|---|
| Receive buffer | Incoming data (SIN) | 256 bytes |
| Transmit buffer | Outgoing data (SOUT) | 256 bytes |

Buffer indices are maintained at:
- $029B (RIDBE): Receive buffer end index
- $029C (RIDBS): Receive buffer start index
- $029D (RODBS): Transmit buffer start index
- $029E (RODBE): Transmit buffer end index

These are wraparound indices into the 256-byte buffers. The buffers are
managed as circular queues (FIFO).

### Memory Impact

Opening the RS-232 device lowers the top-of-memory pointer ($0283–$0284
and $0037–$0038) by 512 bytes. A CLR is executed, destroying all
variables. Therefore, device 2 should be opened before defining any
variables.

## NMI-Driven Bit Banging

RS-232 transmission and reception are driven by NMI interrupts generated
by CIA #2 Timers A and B:

| Timer | Function |
|---|---|
| CIA #2 Timer A | Transmit timing (baud rate) |
| CIA #2 Timer B | Receive timing (baud rate) |

The NMI handler checks the ENABL flag ($02A1) to determine whether to
send or receive a bit:

| Bit | Value | Meaning |
|---|---|---|
| 0 | 1 | System is transmitting |
| 1 | 2 | System is receiving |
| 4 | 16 | Waiting for receiver edge |

The baud rate prescaler value is: `PRESCALER = ((CLOCK / BAUD) / 2) - 100`

## Baud Rate Tables

The Kernal contains prescaler tables for standard baud rates:

| System | Table Address |
|---|---|
| NTSC | $FEC2 |
| PAL | $E4EC |

Separate tables are needed because the prescaler depends on the system
clock frequency (1.02273 MHz NTSC, 0.98525 MHz PAL).

## RS-232 Flag ($02A1)

| Bit | Value | Meaning |
|---|---|---|
| 0 | 1 | System is transmitting data |
| 1 | 2 | System is receiving data |
| 4 | 16 | Waiting for receiver edge |

## Emulation Notes

### Software Emulation Complexity

The RS-232 implementation is entirely software-driven. If the emulator
runs real Kernal ROM, RS-232 functions work automatically as long as:
- CIA #2 timers are correctly emulated
- NMI interrupts are generated at the correct rate
- CIA #2 Port B and Port A bit 2 are correctly connected to the User Port
- The host provides a virtual serial port or network connection

### HLE Approach

If using high-level emulation, the emulator can intercept Kernal RS-232
calls (OPEN, CHKIN, CHKOUT, CHRIN, CHROUT, GETIN, CLOSE for device 2)
and route them directly to a host serial port or network socket. This
bypasses the NMI-driven bit-bang routines entirely but may break software
that directly accesses the RS-232 pseudo-registers or CIA #2.

### Conceptual Considerations for Emulation

For accurate emulation, the RS-232 subsystem should be modeled at the
CIA #2 register level. The Kernal's NMI handler reads and writes CIA #2
Port B bits to transmit and receive data. The emulator provides the
port-level interface; the Kernal software handles the protocol. This is
the most compatible approach but requires precise NMI timing.
